## 二、开源许可证

### 1. 许可证选择

**推荐：Apache License 2.0**

理由：

- 商业友好，允许商业使用
- 明确专利授权
- 要求保留原始版权声明
- 不要求衍生作品开源

### 2. 许可证内容

- 授予使用者：编译、分发、修改代码的权利
- 要求使用者：保留原始版权声明、免责声明
- 不授予：专利侵权诉讼权

### 3. 贡献者协议

**建议：CLA（Contributor License Agreement）**

目的：

- 确保贡献者拥有代码版权
- 授予项目维护者使用贡献代码的权利
- 防止后续法律纠纷

## 九、OS 演进规划与商业插件边界（2026-10-08 更新）

### 1. 演进背景

v0.10.1 开源版已具备 13 功能页 / 15 接口模块 / 54 表 / 48 权限点 / 14 模块的完整基础能力。
下一步的增长瓶颈**不在业务功能数量，而在内核能力**——缺事件总线、工作流引擎、插件运行时、任务 SLA、统一身份治理、模型路由。
因此 v0.11.0 起以「内核先行」为主线，新业务域作为内核的压力测试场。

### 2. 架构分层

| 层 | 内容 | 归属 |
|---|---|---|
| 内核层 | 事件总线、工作流引擎、插件运行时、插件 SDK/清单规范、任务 SLA、统一身份治理、模型路由 | **开源** |
| 域层（六域） | 内容域、渠道域、用户域、数据域、运营域（既有五域）+ **风险域（新增）** | 既有域开源；风险域为商业插件 |
| 插件层 | 官方商业插件（舆情监控、危机公关）、社区插件 | 官方商业插件闭源；社区插件开源 |
| 界面层 | 既有 13 页 + 插件注册页面 | 框架开源，插件页面随插件分发 |

### 3. 开源与商业切分原则

1. **接口开、实现闭**：内核提供稳定插件接口与 SDK，商业插件的实现代码不进入开源仓库；
2. **能力分级**：社区插件享有限能力（单实例、基础限流）；官方商业插件使用完整能力（多源、SLA、审计）；
3. **同一运行时**：商业插件必须通过公开插件接口挂载，不得私有 fork 内核，避免两套代码分叉；
4. **数据隔离**：商业插件使用 `os_` 命名空间建表，跨插件调用一律走事件总线与内核 API，禁止直接跨域查表；
5. **合规优先**：涉及对外发声的插件能力一律人工审核 + 留痕，系统不提供自动外发路径。

### 4. 风险域（新增第六域）交付形态

| 插件 | 版本 | 交付形态 | 说明 |
|---|---|---|---|
| 舆情监控 | v0.12.0（MVP）→ v0.13.0（完整版） | 官方商业插件 | 监测—分析—预警—报告全链路；设计文档存于 `docs_business/` |
| 危机公关 | v0.12.0（MVP）→ v0.13.0（完整版） | 官方商业插件 | 定级—SOP—口径审批—复盘全链路；与舆情域通过事件打通 |

两域与既有五环闭环（接入 / 度量 / 决策 / 执行 / 进化）咬合：舆情域负责接入与度量，危机域负责决策与执行，复盘案例库回补进化环。

### 5. 商业模块目录约束（重要）

为避免商业实现细节进入公开仓库，商业插件相关文档统一存放于 **`docs_business/`** 目录，并在 `.gitignore` 中整目录排除，禁止跟踪：

- 目录：`docs_business/`（PRD、设计稿、数据字典）
- 内容：舆情监控、危机公关及其它官方商业插件的全部设计文档
- 例外：需要公开的仅为内核接口与插件 SDK 文档，存放于 `docs/` 下的公开文档区

> 该约束是对第八章「闭源模块隔离」的延伸：第八章处理**代码隔离**，本章处理**设计文档隔离**。
