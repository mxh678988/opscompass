## 一、竞品新技术扫描（2026 前沿）

### 1.1 语义层 / 指标层（Text2SQL → Text2Metric）——最值得移植

**代表厂商/开源**：dbt MetricFlow、Cube、WrenAI（开源）、DB-GPT（开源）、Vanna（开源）、Snowflake Semantic Views、Databricks Metric Views。

**技术要点**：
- 架构从「大模型直接生成 SQL」升级为「LLM 意图理解 + 语义引擎确定性编译」双脑协同：大模型只声明「我要活跃用户指标，按时间聚合」，语义层用预定义指标图谱编译出精确 SQL。
- 指标定义放在代码/仓库（dbt MetricFlow）或独立语义服务（Cube），天然可版本化、可审计。
- 行级安全（RLS）在编译期注入 WHERE，权限规则不需要 LLM 理解，物理上杜绝越权查询。
- 防幻觉护栏：AST 解析校验生成的 SQL + 数据库只读连接 + 白名单指标。
- dbt 2026 基准：大模型直接生成复杂 SQL 准确率最高约 64.5%；限定在语义层内近乎 100%。

**可移植性评估**：OpsCompass 后端已有数据源驱动（PostgreSQL/ClickHouse/MySQL）+ 模型路由（M6），只需新增「指标注册表（Metrics Registry）+ 指标解析编译层」即可落地，无需引入重型外部系统。中高工作量，价值极高。

### 1.2 数据智能体 / 多智能体协同

**代表厂商**：思迈特 Smartbi 白泽 V5、神策 Sensors AI 1.0、GrowingIO 分析云、火山引擎 DataFinder、探域运营智能体（国内 2026 密集发版）。

**技术要点**：
- 多智能体协同：分析 Agent（采集诊断）+ 执行 Agent（交付落地），人工确认节点插入。
- 统一指标模型：所有 Agent 基于同一套业务口径问数，避免各说各话。
- ReAct + Skills + RAG：Agent 按「推理-行动-观察」循环调用技能与知识库，输出带归因证据链。
- 场景化封装：门店运营/用户生命周期/活动运营/商品运营等开箱即用 Agent。
- 智能洞察标配：看板智能总结、异常识别、多维归因、预测（流失/转化/Lookalike）。

**可移植性评估**：OpsCompass 已具备插件运行时（M2）+ 工作流（M5）+ 模型路由（M6），只需新增「运营 Agent 编排层」即可把现有能力包装成场景化 Agent；知识库（v0.14.0 KnowledgeCenter）可作 RAG 底座。中等工作量，价值极高。

### 1.3 AI 分析与归因证据链

**技术要点**：
- 看板/卡片智能洞察：AI 自动识别异常波动、隐藏关联、给出可行动建议（观远、DataFinder）。
- 多维归因 + 证据链：结论可追溯到具体指标、维度、数据源与计算路径（思迈特白泽）。
- 预测类能力：流失预测、转化预测、概率分布、Lookalike 人群扩散（GrowingIO）。
- 字段级血缘：一键查看卡片字段上下游，评估改动影响面（观远）。

**可移植性评估**：异常检测可用统计方法（3σ/EWMA/同比环比）先落地，不依赖大模型；归因证据链可对接已有事件总线（M1）与审计日志。低-中工作量，价值高。

### 1.5 竞品共性趋势（总结）

1. **语义层成为 AI 问数的事实标准**：确定性编译取代模型硬猜，准确率与安全双升。
2. **AI 智能洞察是标配**：看板总结、异常识别、自动报告、多维归因。
3. **从「分析」走向「执行」**：运营智能体一句话驱动全流程，双 Agent 协同 + 人工确认。
4. **场景化封装**：面向运营具体场景出开箱即用 Agent，而非通用对话。
5. **预测能力主战场**：流失/转化预测、概率分布、Lookalike。
6. **数据治理前置**：血缘、RLS、口径统一、审计合规。

## 三、UI 大力美化方案（体验升级）

### 3.1 设计基调（基于现有 ui-design-tokens.md 扩展，零冲突）

- 深色模式为第一公民：深灰（如 #1e1e24/#17171c）而非纯黑，减少 OLED 光晕与视觉疲劳；浅色模式保留。
- 排版遵循 F-Pattern：重要信息左上优先，卡片化承载信息层级。
- 栅格与间距：统一 4px 基准栅格，页面级留白 ≥ 24px，卡片内边距 ≥ 16px。
- 圆角/阴影/动效：圆角 8-12px 分层级；阴影 3 档（悬浮/浮起/弹层）；微动效 ≤ 240ms，尊重 prefers-reduced-motion。

### 3.2 视觉系统改造

| 模块 | 现状 | v0.15.0 目标 |
|---|---|---|
| 设计令牌 | :root 变量已定义 | 扩展为明暗双套令牌 + 语义化命名（bg-surface / text-muted / border-subtle） |
| 布局 | 默认侧边栏常驻 | 可折叠侧栏（宽度记忆化），内容区自适应 |
| 看板卡片 | 静态数据 | 卡片悬浮阴影 + hover 微交互 + 异常徽标 |
| 图表 | 默认 ECharts 皮肤 | 定制主题（品牌色/渐变/字体），统一 tooltip 样式 |
| 状态反馈 | 少量 | 骨架屏（加载）、空状态插画（无数据）、错误态（重试引导） |
| 字体 | 系统字体 | 引入品牌字体栈（中文 PingFang/MiSans 优先级 + 数字字体） |
| 动效 | 无 | 路由切换淡入、数字滚动（count-up）、图表入场动画（动画关闭开关） |

### 3.3 Next Best Action（NBA）组件

- 首页顶部「行动卡」：基于今日异常/待办/规则命中，推荐 1-3 个最高优先级行动（如「昨日新客转化率下降 12%，建议检查投放计划」）。
- 数据来源：运营参谋结果 + 规则引擎命中 + 定时任务待办。

### 3.4 组件化沉淀

- 梳理高频组件（数据卡片、状态徽标、空状态、筛选条、分页条）统一封装为前端公共组件库目录 `src/components/`，消灭散落重复实现。
- 骨架屏 + 虚拟滚动作为性能与体验双重手段，统一在列表/看板场景启用。

## 四、性能优化方案（Core Web Vitals 对标）

### 4.1 前端

| 优化点 | 做法 | 预期收益 |
|---|---|---|
| 数据加载 | 大数据量走 Web Worker 处理（转换/聚合），主线程不阻塞 | 交互流畅度显著提升 |
| 图表渲染 | ECharts `appendData` 增量渲染 + `animation:false`（大数据）+ LTTB 降采样 | 万点以上不卡顿 |
| 长列表 | 虚拟滚动（表格/日志/消息） | 千行级列表滚动 60fps |
| 首屏 | 路由级懒加载 + 骨架屏 + 关键资源 preload | 首屏 LCP ↓ |
| 渲染 | 对非首屏内容用 `content-visibility: auto` | 整页绘制成本下降 |
| 打包 | Vite 拆 chunk、按需引入 ECharts 模块、gzip/brotli | 包体显著缩小 |

### 4.2 后端/数据库

| 优化点 | 做法 | 预期收益 |
|---|---|---|
| 查询缓存 | 指标查询结果 Redis 缓存（TTL 分层：分钟级/小时级） | 热查询命中率 ↑ |
| 连接池 | SQLAlchemy 连接池参数调优 + pg_stat_statements 慢查询扫描 | 连接抖动消除 |
| 大数据集 | 聚合下推数据库/数据源端完成，应用层只做展示切片 | 传输量与内存双降 |
| 分页 | 大数据集游标分页（keyset）替代 offset 深翻页 | 深页性能稳定 |

## 五、稳定性优化方案

### 5.1 容器与编排

- Docker Compose 增加 `healthcheck`：PostgreSQL 用 `pg_isready`、Redis 用 `redis-cli ping`。
- 服务间 `depends_on: condition: service_healthy`，杜绝启动顺序竞态。
- 容器资源上限（mem_limit/cpus）防单容器拖垮宿主。

### 5.2 可观测性（OpenTelemetry 优先）

- 埋点：HTTP 请求（FastAPI middleware）、DB 查询、LLM 调用、定时任务执行，输出 traces + metrics + logs 三合一。
- 错误上报：统一异常处理器，关键业务错误聚合展示（自带运营参谋页，不依赖外部平台）。
- 健康页：`/health` 汇总各依赖（DB/Redis/数据源/模型路由）状态，供外部监控探活。

### 5.3 数据与任务

- 定时任务：执行超时熔断、失败重试（指数退避）、幂等键防重入。
- 事件总线（M1）：消费端失败进入重试队列，死信可人工重放。
- 备份：PostgreSQL 每日 pg_dump 保留 N 天；关键表导出 JSON 快照。

## 六、安全性优化方案

### 6.1 认证与会话

- JWT 短时效（如 15min）+ httpOnly Cookie 承载刷新令牌，CSRF 双校验（SameSite + 自定义头）。
- 登录接口限流（IP + 账号维度）与失败锁定（连续 N 次锁 M 分钟）。
- 密码策略：bcrypt/argon2 迭代参数升级，禁用弱口令列表。

### 6.2 供应链与配置

- 前端 CSP（Content-Security-Policy）收紧：禁止 inline script，仅信任自有 CDN。
- 依赖：lock 文件锁定版本 + 定时漏洞扫描（pip-audit / npm audit）。
- SBOM 清单：构建期生成（cyclonedx），发布包附校验。

### 6.3 LLM 安全（对接 OWASP LLM Top 10）

- 提示注入防护：llm-guard 类输入净化 + 系统提示隔离，用户内容与指令分区。
- 工具调用最小权限：模型路由只暴露白名单工具，涉及写操作必须人工批准（人工确认节点）。
- 输出校验：LLM 输出经结构化解析（JSON schema）后入库，不直接拼接执行。
- 敏感信息：日志脱敏（API Key/手机号/密码），凭据不落明文。
