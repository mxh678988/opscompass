# 运营智脑 OpsCompass · 移动端三端规划（iPhone / 鸿蒙 / 安卓）

> 版本：v0.10.1 | 生成时间：2026-10-02 | 状态：规划中
>
> 本文档将 **iPhone（苹果）手机版、鸿蒙手机版、安卓手机版** 统一纳入 OpsCompass 整体规划。
> 与 `docs/HARMONY_PLAN.md`（鸿蒙专项构思）为引用关系：鸿蒙专项章节继续有效，**排期与预算口径以本文档为准**。

## 一、排期位置（硬约束）

三端移动应用 **不参与本轮发布**，启动条件为前置任务全部达成：

```
① 各市场 / 应用商店发布成功（微软商店、华为应用市场、应用宝等）
        ↓
② Mac 系统应用开发（含 macOS 桌面版发布）
        ↓
③ 移动端三端开发（iPhone → 鸿蒙 → 安卓，按本文档排期）
```

- 该顺序沿用既定决策：**Mac 系统应用开发排在所有发布任务之后**，移动端三端随其后。
- 节奏与产品策略一致：**每季度一个稳定小版本**，不并行堆功能。

## 二、产品定位与形态

| 项目 | 说明 |
|---|---|
| 定位 | 移动端为「伴随端」而非全量后台：看板查看、实时告警、审批流转、数据录入、消息通知 |
| 后端 | 100% 复用现有 FastAPI 后端与 OpenAPI 接口，**服务端零改动**（仅需网关/鉴权适配） |
| 数据 | 复用现有数据模型、缓存策略；移动端默认只读 + 轻写入 |
| 账号 | 与桌面端同一套账号体系，支持扫码登录 / Token 续期 |

## 三、技术选型对比

| 方案 | 技术栈 | 优点 | 缺点 | 三端覆盖 |
|---|---|---|---|---|
| **A. PWA（渐进式 Web）** | React + 现有前端 | 成本最低、当天可验证；复用现有前端 100% | 推送/离线/系统能力受限；iOS 限制较多 | 三端浏览器通用 |
| **B. ArkUI-X（推荐主路线）** | ArkTS / ArkUI | 华为官方跨平台框架，一套 ArkTS 代码输出 HarmonyOS / Android / iOS；与 `HARMONY_PLAN.md` 的 ArkTS 路线一致 | 生态较新，iOS 侧成熟度需实测验证 | 一次开发，三端产物 |
| **C. Flutter** | Dart | 生态成熟、UI 一致性好 | 鸿蒙需依赖社区适配分支，非官方主线 | 三端（鸿蒙需适配分支） |
| **D. 三端原生** | SwiftUI / ArkTS / Kotlin | 体验与性能最优、系统能力最完整 | 成本最高，约等于三套独立开发 | 三端各写一套 |
| **E. React Native** | RN + RNOH | 可复用 React 心智，社区鸿蒙适配（RNOH）已推进 | 三端版本管理复杂，鸿蒙侧仍属适配层 | 三端 |

**推荐组合（分阶段）**

1. **阶段一 · PWA 先行**：复用现有 React 前端做移动端适配，最低成本验证移动场景真实需求，无需上架即可内测。
2. **阶段二 · ArkUI-X 主路线**：以 ArkTS 一套代码产出鸿蒙 / 安卓 / iPhone 三端，与鸿蒙专项规划同源，避免三份维护成本。
3. **阶段三 · 原生增强（按需）**：仅对性能敏感模块（图表渲染、长列表、推送）下沉原生实现。

> 备选：若 ArkUI-X 在 iOS 侧实测不达标，则退回「Flutter（iOS + Android）+ 鸿蒙 ArkTS 原生」双轨方案。

## 六、上架渠道与账号成本

| 端 | 渠道 | 产物 | 开发者账号 | 费用 |
|---|---|---|---|---|
| iPhone | App Store、TestFlight（内测） | .ipa | Apple Developer Program | **$99 / 年** |
| 鸿蒙 | 华为应用市场（AppGallery）、应用宝（鸿蒙版） | .hap | 华为开发者联盟（需企业认证） | 免费（认证免费） |
| 安卓 | 应用宝、华为 / 小米 / OPPO / vivo 应用商店、酷安 | .apk / .aab | 各市场开发者账号 | 免费 |
| 安卓（海外） | Google Play | .aab | Google Play 开发者账号 | $25 一次性 |

**签名要求**：iOS 由 Apple 证书体系强制签名；鸿蒙需华为签名证书；安卓使用自有签名证书（自签免费，需妥善保管 keystore）。
**合规要求**：三端均需提供隐私政策 URL、权限用途说明、软件著作权/备案信息（国内安卓市场普遍要求）。

## 七、预算估算（人天，估算值）

| 工作项 | 人天（下限） | 人天（上限） | 备注 |
|---|---|---|---|
| PWA 移动适配 | 15 | 25 | 复用现有前端，改动集中在校验与布局 |
| ArkUI-X 三端基础框架 | 25 | 40 | 工程搭建、路由、网络层、鉴权 |
| iPhone 端适配与上架 | 20 | 35 | 含证书、审核整改 |
| 鸿蒙端适配与上架 | 25 | 45 | ArkTS 生态较新，预研成本偏高 |
| 安卓端适配与上架 | 20 | 35 | 多市场适配与提审 |
| 三端测试与验收 | 25 | 40 | 兼容性机型覆盖 |
| **合计** | **130** | **220** | 采用 ArkUI-X 一套代码路线 |

**对照：三端各写原生** 约 **210 ~ 330 人天**；**PWA 单路线** 约 **20 ~ 30 人天**（但系统能力受限）。
**现金成本**：Apple $99/年 + Google Play $25 + 华为/安卓各市场免费 + 私有签名与公证杂项，**首年现金支出约 ¥1,000 以内**（不含人力与设计外包）。

> 上述人天为规划估算，用于排期与资源决策，非承诺值；实际以后续技术预研报告为准。

## 八、复用策略（降低三端成本的关键）

| 复用对象 | 复用率 | 说明 |
|---|---|---|
| 后端 API / OpenAPI | 100% | 与平台无关 |
| 数据库模型 | 100% | SQLAlchemy 模型零改动 |
| AI 服务集成 | 100% | 接口一致 |
| 前端业务逻辑 | 70 ~ 80% | React 逻辑可迁移至 ArkTS |
| UI 设计令牌 | 100% | `docs/ui-design-tokens.md` 直接沿用 |
| 测试用例 | 70% | 单元测试可复用，UI 测试需重写 |
| 部署链路 | 100% | 后端仍以 Docker 交付 |

## 九、风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| ArkUI-X 在 iOS 侧成熟度不足 | 高 | S1 预研阶段先做三端 PoC，不达标即切 Flutter 双轨 |
| 鸿蒙生态与 API 迭代快 | 中 | 锁定 SDK 版本，季度评估升级 |
| 三端审核整改耗时 | 中 | 提审前完成隐私政策、权限说明、备案材料准备 |
| 多端维护成本失控 | 中 | 坚持「一套代码 + 原生增强」，禁止三份并行开发 |
| 移动端需求与桌面端背离 | 低 | 需求分析阶段明确「伴随端」边界，不做全量后台 |
